# Native runtime integration for Mechanism IR v0.2

The runtime consumes the unchanged executable contract from architecture commit `ea8f6b7b324f9f0fd0091b52052486374de4f4e7`. It performs no migration or inference automatically. The custodian supplies a v0.2 mechanism and an explicit layout policy. Both `composer-request/0.1` and `composer-request/0.2` envelopes are accepted for a v0.2 mechanism; dispatch is by `mechanism.ir_version` and does not invoke the legacy HCNO semantic validator.

Use `probes/run_composer.py validate|seed|compose --request REQUEST --out NEW_DIRECTORY`. Compose also requires `--seed SEED_DIRECTORY --native NATIVE_FRAGMENT_DIRECTORY`. The existing `probes/run_paired_candidate.py` wraps seed, native cleanup, compose and independent CDX/CDXML reopening with immutable inputs and bounded workers. Existing output paths are rejected.

The seed and composition receipts retain `ir_sha256`, `chemical_inventory_sha256` and `depiction_plan_sha256`, plus the exact lowered plan and compiled flows. Native geometry receipts bind their input files, source hashes, visible atom manifest, style and native binary identity. A caller-supplied plan must equal deterministic lowering of its supplied IR. Chemical inventory remains complete even when its depicted subset is smaller. Original source/sink ports remain in each routed flow's `lowered_ports` record.

The adapter uses all 118 contract element identities to encode atomic numbers. This is an encoding capability, not native execution or chemical validity for every element. Native readback compares serialized identity/H/charge/isotope fields and the depicted bond graph. When `NumHydrogens` is omitted, a narrowly qualified native formula observation may provide H for ordinary bonded neutral carbon. All other missing-H cases remain `NATIVE_HYDROGEN_UNVERIFIED`; no H is inferred from a valence table or replaced with expected IR values.

The native worker automatically records `native-atom-readback/0.4` sidecars for v0.2 seeds. It selects each eligible carbon atom in its original native graph and reads **`Document.Selection.Objects.FormulaHTML`** only after observing exactly one selected native object, one selected atom with the same ID, and zero selected bonds. It verifies unchanged whole-document native SMILES and saves a separate after-selection CDXML. Both the executor and consumer compare every native atom/bond attribute, including IDs, mappings and endpoints, before/after selection. `verify_geometry_receipt` checks the sidecar filename/hash, source CDXML hash, after-selection filename/hash, graph equality, complete observation coverage and actual atom identities before exposing the sidecar to the adapter. This is an audited local-executor boundary, not authentication against an attacker able to rewrite that executor and its receipts.

Formula H is parsed from a strict one-carbon expression; the superscript bullet suffix represents bonds outside the selection and must match the serialized bond-order sum and native `UsedValences`. `UnusedValences` and `NumImplicitHydrogens` remain raw observations and do not supply or override H. Profile `native-carbon-selection-formula-h/0.2` requires normal neutral carbon, no native isotope/radical/query/abnormal-valence flag, implicit H allowed, positive integer bond valence and H counts 0-3. The earlier acyclic profile remains supported. At most one directly bonded explicit H or D is allowed in that acyclic profile: its native node must have zero charge and label H, isotope 0 or 2, and exactly one single bond to the carbon. Separate native C-F-H and C-F-D controls returned `CH2` rather than total attached H3, with exact selection and unchanged-graph checks. Multiple explicit hydrogen neighbors and other hydrogen isotopes remain unqualified. Existing explicit CDXML `NumHydrogens` observations retain their independent path. Unknown expressions or profiles fail explicitly; valid element identities are never deleted to satisfy this native capability boundary.

The cyclic extension checks the **entire connected native component**, not only the selected atom or its formula. It accepts exactly one saturated 3-8 member carbon cycle, optionally bearing saturated carbon trees. Every component atom must satisfy the native neutral, non-isotopic, non-radical normal-carbon flags, and every bond must be single. Removing terminal trees must leave a cycle containing the selected atom with degree two at every remaining node. This rejects carbonyl-containing components, unsaturation and Kekulized aromatics, heteroatoms and explicit H/D, charges/isotopes/radicals, and fused/spiro/bridged/joined cycles. Ring sizes outside 3-8 remain unqualified. The graph determines only a capability profile; H still comes exclusively from native FormulaHTML or explicit CDXML.

The existing frozen route search constants are unchanged. A v0.2 composition that reaches a layout or route-clearance frontier records failure; if a scene was generated, its first scene/mapping/CDXML is retained and the paired runner does not continue to final native export. No reference-based layout correction or automatic retry is performed.

`stage-result.json` separates checked semantic invariants from native capability or geometry failure. A successful stage is not full chemical validity, physical-size visual acceptance, product acceptance or Gold. The legacy `verify_composition.py` has no v0.2 depicted-subset contract; do not use it to certify v0.2 output. The independent architecture evaluator remains a separate integration boundary.

The bounded H investigation retained seven original property-control pairs and their new-process readback equality; warned ethane was kept separately. The final production worker ran seven further synthetic controls. Six were warning-free and supplied eight qualified carbon observations with H=0/1/2/3, including separate directly bonded H and D cases. Methane/H4 had a warning and two selected native objects, so the worker rejected its selection before reading FormulaHTML and it supplies no fallback qualification. Earlier dispatch errors (`Selection.Item` and `Selection.Formula`), the provisional valence-only artifacts, and the first new integration rejection before explicit H/D qualification remain retained. `Selection.Count` is not a native collection count: the correct member chain ends at `Selection.Objects.Count`.
